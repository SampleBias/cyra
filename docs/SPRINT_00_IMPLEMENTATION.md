# Sprint 00 implementation and verification

Project: **Cyra — Cybernetic Cellular Intelligence**. Date: 2026-10-22. Implementation owner: Codex, acting on the user's instruction to begin the build. Independent engineering/scientific review: pending. This report concerns software infrastructure, not cell physiology.

## Implemented scope

- Pinned Rust workspace with `cyra-core`, `vmcell` and development-only `xtask`.
- Human and JSON commands for version/capability/schema inspection; sequential stdin/stdout JSONL protocol.
- Strict duplicate-key, field, ID, depth, container, line and session limits; typed status/exit codes and recoverable errors.
- Distinct reserved association/intervention/counterfactual request types; typed evidence origins, validation and uncertainty statuses.
- Honest refusal of future scientific commands with null results and unresolved model metadata.
- Generated JSON Schemas with drift tests; actual compiler/target/profile embedded at build time.
- SHA-256 content-addressed artifacts, canonical JSON, private permissions, descriptor-relative path access, atomic no-overwrite publication and integrity verification.
- Pinned CI workflow, dependency/license policy audit, source/evidence inventory, governance templates and contributor instructions.

No biological parameters, measured donor data, fitted mechanisms, causal algorithms, ODE engine or AI integrations were added. A command's presence in the planned-operation list does not mean its scientific implementation exists.

## Platform and reproducibility contract

Reference platform: Linux x86_64, AMD Ryzen 5 1600 (6 cores / 12 threads), Rust 1.97.1. Actual compiler and platform data are captured in each evidence run. Deterministic hashes depend on `cyra-json-v1`, the pinned serialization version and the input content. Execution timing is separate and varies between runs. There is no scientific RNG in this sprint.

Foundation budgets: 1 MiB line, depth 64, 4096 container items/session requests, 16 MiB artifact payload. Reference release startup target: capabilities p95 under 100 ms over 30 launches after 3 warmups. Agent memory target: observed peak resident size under 64 MiB after one version request. Actual values are in `performance.json`; these are engineering workloads, not simulation benchmarks.

## Limitations and handover

Original source is released under the MIT license. Workspace packages remain `publish = false` and are not published to crates.io. Only the Unix reference path is supported for filesystem security. Abrupt termination can leave unpublished staging files; complete artifacts are never exposed before publication. Owners can modify files outside the API, so verified reads detect corruption.

Dependency audit checks licenses/native-build policy and is not a vulnerability advisory scan. Reserved scientific-query schemas will need explicit units, time and full provenance extensions in their later implementation sprints. JSONL sessions are bounded and synchronous; per-simulation quotas are future work. Scientific runtime has no network implementation.

No Git commit was created: the environment supplies a read-only `.git` placeholder. Source revision evidence uses the sorted source-inventory SHA-256 instead. Independent reviewers must record their actual identities and decisions; this implementation does not invent their sign-off. Sprint 01 measurement ingestion now has its own [implementation report](SPRINT_01_IMPLEMENTATION.md). Sprint 02 is the next engineering package. This Sprint 00 report is not a claim about later sprints.
